# 2.7.0 验证范围（2026-10-17）

## 自动检查与远程推理

- 44 项 Vitest、26 项 Python 后端测试、TypeScript 类型检查、构建及安装包检查通过。
- 协议回归覆盖能力握手、SHA256 资源上传与去重、真实进度、图片取回、允许目录边界、参考图快照、旧 Images 接口兼容，以及现有预设引用保持不变。
- 独立 Windows / RTX 4090 D 部署使用 ComfyUI `e087d8f6cb7c6cdb11b59dc7c9bf17c79f8d877d`，官方 Qwen Image 2.1 INT8 底模及 INT8 Union 控制权重；不改动原有视频生产部署。
- 9 组 512×512 真实推理：基础、LoRA、ControlNet 强度 0 和 1、蒙版、LoRA+ControlNet+蒙版+负向/CFG 组合、参考变体，以及 FlowMatch/SeedVR2 调度器。默认使用 20 步；参考变化幅度 0.45 实际采样 9 步。
- 第三方 LoRA 0.7 与无 LoRA 的同种子图有真实像素差异；移除 LoRA 且控制强度为 0 时与基础图一致，未沿用上次效果。控制图边缘余弦相似度从 0.355 提升到 0.510；这是本组控制图验证，不代表所有构图都能自动评定。
- 单独蒙版及全部组合中，黑色区域与同尺寸原图逐像素一致，白色区域发生变化。错误模型 LoRA 匹配不到层时明确失败；真实 1024×1024 任务采样到第 2 步后取消成功。

## 原生 DSH 验收

- 用户手动重启加载 2.7.0 后，原生高级设置已启用远程能力。通过 macOS 文件选择器依次导入普通茶壶原图、黑白蒙版和边缘控制图；从资源库选择已有 LoRA，设置权重 0.7、控制强度 0.8、负向词、CFG 2.5、linear。
- 另存独立测试预设，未覆盖已有预设或修改默认项。创作页 512×512、40 步任务完成，任务耗时约 32 秒；观察到 15/40，切到会话再返回继续显示 26/40。
- 在已有专用验收会话中，DeepSeek-V41-Flash 使用预设工具加载该组合，再调用 `qwen_generate_image`；未运行独立脚本。会话显示 9/40，切到创作页继续显示 13/40、33/40。该任务约 28 秒完成，模型整轮约 45 秒。
- 完成后会话图片卡片与创作页均显示茶壶结果；隐私图库中存在两张新图，普通收藏图库不混入未收藏结果。
- 两份任务记录均保留 LoRA、控制图、原图/蒙版、负向词、CFG、调度器和真实 40/40。两张图的蒙版黑色区域最大像素差均为 0。
- 原有全部预设条目和默认 ID 与备份逐项相同；仅新增独立验收预设。本轮未删除原图库或更换连接设置。

## 限制

- 上述耗时仅代表这台机器的 512×512 组合测试；首次模型加载、首次大文件同步或更大尺寸会更慢。不同后端相同种子不保证相同像素。
- Windows NVIDIA 已实测，POSIX 启停代码并不代表 Linux 已通过真实 GPU 验收。普通 Images 服务没有高级协议时仍只支持基础生图。
- 结构控制需要已经准备好的控制图，插件不自动从照片提取人体姿态；参考变体不等于精准指令编辑。CI 不运行 GPU 推理。
